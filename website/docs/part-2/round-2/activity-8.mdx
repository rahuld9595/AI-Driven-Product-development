# 8. Integration Testing

## Objective

Validate behavior across component boundaries using realistic but safe, non-sensitive contracts, dependencies, and test data.

## Steps

1. Identify the boundary under test: service, database, queue, API, or UI flow.
2. Define contract expectations and failure scenarios.
3. Use synthetic fixtures or approved non-production data.
4. Automate the test in continuous integration where feasible.
5. Document test-environment gaps and reliability limits.

## Evidence of completion

A CI-executed integration test with a documented contract and at least one failure-path assertion.
