# 4. Encode a Pattern (Optional)

## Objective

Capture a proven implementation or delivery pattern so it can be reused deliberately rather than regenerated inconsistently.

## Steps

1. Select a pattern already reviewed and validated.
2. Describe purpose, constraints, inputs, outputs, and trade-offs.
3. Provide a minimal public or synthetic example.
4. Define when the pattern should and should not be used.
5. Add checks that preserve its key guarantees.

## Evidence of completion

A pattern document plus a second application of it that required no rework.
