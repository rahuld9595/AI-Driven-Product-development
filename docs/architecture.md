# Architecture

## Why content sits outside the framework

Course content lives in `website/docs/` as plain Markdown and MDX. The framework configuration lives
beside it in `website/`. A writer editing an activity page touches one Markdown file and never the
build configuration.

## Build pipeline

```text
website/docs/*.md(x)
        |
        v
  Docusaurus 3 (MDX 3)  <-- sidebars.ts, docusaurus.config.ts
        |
        v
   website/build/  (static HTML, CSS, JS)
        |
        v
  GitHub Pages via Actions
```

## Routing

| Path | Source |
| --- | --- |
| `/` | `website/src/pages/index.tsx`, redirects to the Welcome page |
| `/docs/*` | `website/docs/`, via `routeBasePath: 'docs'` |

The root route exists specifically so the navbar home link resolves. Without it, `onBrokenLinks:
'throw'` fails the build on every page.

## Sidebar strategy

Top-level pages are listed explicitly in `sidebars.ts`. Activity directories use `autogenerated`
entries ordered by `sidebar_position`, so adding an activity requires no navigation edit. The
trade-off is that a stray file in one of those directories appears in navigation automatically;
`tests/sidebar.test.mjs` exists to make that visible.

## Failure modes worth knowing

| Symptom | Cause |
| --- | --- |
| Build fails on an internal link | `onBrokenLinks: 'throw'`. Fix the link; do not lower the setting. |
| Build fails parsing an MDX file | A raw `{` or `<` outside a code fence. |
| A page renders but is missing from navigation | Not registered in `sidebars.ts`. `npm test` catches it. |
| Works locally, fails in CI | Link case mismatch. macOS is case-insensitive; CI is not. |
