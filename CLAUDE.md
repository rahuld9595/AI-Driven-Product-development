# Repository rules

Durable guidance for both human contributors and AI assistants working in this repository. Keep this
file short, specific, and current. Task-specific instructions belong in the relevant page or a
`.claude/skills/` definition, not here.

## Project shape

- Course content is Markdown and MDX under `website/docs/`.
- Engineering notes about the repository itself are under `docs/` at the root. Do not confuse the two.
- Navigation is declared in `website/sidebars.ts`.
- Activity pages under `website/docs/part-2/round-*/` are autogenerated into the sidebar and ordered
  by `sidebar_position`. A new activity needs no sidebar edit; a new top-level page does.

## Content conventions

- Front matter must set `id` and `title`. `tests/frontmatter.test.mjs` enforces this.
- Exactly one H1 per page.
- Prefer short sections with descriptive H2 headings; the right-hand table of contents is built from them.
- Use Docusaurus admonitions (`:::note`, `:::tip`, `:::warning`, `:::info`) rather than bold paragraphs.
- Use relative links between pages, including the file extension, so the build validates them.
- Every activity page states an objective, the steps, and the evidence that demonstrates completion.

## MDX constraints

`.mdx` files are parsed as MDX: curly braces and raw angle brackets are read as expressions or JSX.
Wrap them in backticks or escape them. This is the most common cause of a build failure here.

## Verification

Run both from `website/` before opening a pull request:

```bash
npm test
npm run build
```

`onBrokenLinks` is `throw`, so a broken internal link fails the build. CI runs the same commands on
pull requests.

## Boundaries

- This repository is public. Never add confidential business information, internal source code,
  ticket identifiers, customer data, credentials, or employer branding.
- Exercise material must be synthetic, public, or explicitly approved for public use.
- Treat generated content as untrusted until a human has reviewed it.
- A human approves every merge. Agents propose and explain changes; they do not merge them.
